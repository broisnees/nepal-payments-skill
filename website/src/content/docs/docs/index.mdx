Nepal Payments is an [Agent Skill](https://agentskills.io) for integrating Nepali payment gateways into any backend, web app or mobile app. Ask a coding agent to "add eSewa and Khalti checkout to this app" and it follows a tested recipe: server-side signing, server-to-server verification, exactly-once fulfilment and reconciliation.

The skill ships working adapters in {languages.length} languages, covered by {totalTests} tests that include each provider's own signature test vectors. The adapters also work on their own, without any agent.

## What the skill enforces

- Secrets and signing stay on the server. Clients only send an order id.
- A redirect or callback is never proof of payment. The provider's status API decides.
- Verification uses the amount and ids from your database, not from the callback.
- State changes go through one tested function, `decideTransition`, which handles early return-URL hits, late payments after an attempt was closed, missing or mismatched amounts and duplicate payments.
- A reconciliation job settles payments where the customer closed the tab.

The reasoning behind each rule is in [Production architecture](/docs/guides/architecture/).
