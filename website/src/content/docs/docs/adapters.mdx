Each language has the same shape: build the configured providers from environment variables, call `initiate()` to start a payment, then call `verify()` from your return handler with the values you stored. All amounts are integer **paisa** (1 NPR = 100 paisa).

## 1. Copy the adapter

| Language | Copy | Notes |
|---|---|---|
| TypeScript | `scripts/ts/src/` | Keep `core.ts`, `index.ts` and the providers you need. Files import each other with `.ts` extensions; rewrite to `.js` for NodeNext or extensionless for bundlers if your tsconfig lacks `allowImportingTsExtensions`. |
| Python | `scripts/python/nepal_payments/` | Stdlib only. Add `cryptography` for connectIPS. |
| Java | `scripts/java/src/main/java/np/payments/` | JDK 17+, no dependencies, blocking and thread-safe. |
| Kotlin | `scripts/kotlin/src/main/kotlin/np/payments/` | kotlin-stdlib only, `suspend` API. Server side only, never inside an Android app. |
| PHP | `scripts/php/src/` | Namespace `NepalPayments`. Register it in your PSR-4 autoload. |
| Go | `scripts/go/payments/` | Stdlib only. Copy into your module, for example `internal/payments/`, and fix the import path. |

## 2. Configure

Set the environment variables for each provider you want. A provider is enabled when its required variables are present. The full list is in [Environment variables](/docs/guides/env/).

```bash
ESEWA_ENV=sandbox
ESEWA_PRODUCT_CODE=EPAYTEST
ESEWA_SECRET_KEY='8gBm/:&EnhH.1/q'
KHALTI_SECRET_KEY=...            # from test-admin.khalti.com
KHALTI_WEBSITE_URL=https://shop.example.com
```

## 3. Initiate and verify

`initiate()` returns a **redirect** (send the browser to `url`), a **form** (render an auto-submitting POST; every port has a `renderAutoSubmitForm` helper) for NEPALPAY QR, a **qr** (show `qrImage` or render `qrString`, then poll `verify()`; there is no return URL), or for GetPay, an **sdk** (load `scriptUrl` and start GetPay's card checkout with `options`; the adapter renders the checkout, payment and return pages, and `verify()` takes the return `token`). Store the `providerRef` it returns on the attempt: Khalti's `pidx`, NPS's `ProcessId`, IME Pay's token and NEPALPAY QR's `validationTraceId` are needed by `verify()`. Hamro Pay's `sessionId` isn't, but keep it for support.

<Aside type="danger" title="Never fulfil from the callback alone">
  Pass the amount and ids from your database into `verify()`, then apply the result with `decideTransition` and a guarded `UPDATE`. Fulfil only when the new status is `paid`. [Production architecture](/docs/guides/architecture/) has the table schema, the return handler and the reconciliation job.
</Aside>

## 4. Wire the routes

Every framework needs the same five routes. [Web frameworks](/docs/guides/web/) has complete handlers for Express, Hono, Next.js, FastAPI, Django, Laravel, Spring Boot and Ktor, plus notes for Go `net/http`, chi and Gin. Mobile apps reuse those routes; see [Mobile apps](/docs/guides/mobile/).
